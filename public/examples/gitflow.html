How to read it

Time runs downward. Circles are commits; squares identify numbered events. Arrows show chronological work and merges, not Git parent pointers. Two feature tracks share one branch family. Color is reinforced by named lanes.

In this example the hotfix happens after the release closes. With an active release, merge a hotfix into that release instead of develop; the release later carries it back.

Source and model notes

Based on Vincent Driessen’s A successful Git branching model (original illustration: CC BY-SA). Independently drawn here; no original artwork reused. “Main” replaces the original “master.” Gitflow suits scheduled, versioned releases; it is not a universal recommendation for continuous delivery.
