Implementation plan: make editing happen on the canvas

20 September 2026 · Proposed work, not completed features

First release: put a shape where you want it, type a readable label, connect it, and resize it—without leaving the diagram or losing work. Ship slices 0–4 together as the first complete editing loop. Then improve routing and reuse.

This is an incremental change to the existing JavaScript modules and native Pikchr renderer. No framework migration, replacement drawing engine, account system, or general-purpose SVG editor.

The editing contract

  1. Pikchr source stays authoritative. Every supported canvas operation produces a source patch and is validated by the existing WASM renderer. The accepted SVG and object geometry come from that same validated source revision. Never save a drawing that only exists as modified SVG.
  2. One preview, explicit state. The canvas shows the complete current draft in queue mode, or the applied document in auto-apply mode. Display “Applied,” “Draft: N changes,” or “Invalid input—showing last valid diagram.” A temporary drag outline is visibly a preview, not a saved result.
  3. One semantic operation, one transaction. A text session, resize drag, or connected-node insertion is a single edit. Auto-apply gives it one Undo step. Queue mode gives it one draft step; Apply all remains one committed batch that Undo can reverse.
  4. No silent approximations. Unsupported expressions, nested groups, macros, and ambiguous mappings remain inspect-only. Show a reason and an explicit source-edit action. Preserve untouched source, comments, and Unicode byte boundaries.
  5. Exported geometry has no hidden dependencies. Store optional sizing preferences and gesture settings in versioned local document metadata. Export dimensions and wrapped label lines in Pikchr itself; a clean renderer must reproduce the result without that metadata. If imported source cannot recover an editing preference, show it as unspecified instead of guessing.
  6. Selection does not steal focus. No automatic jump to the source editor. Gesture cancellation, failed validation, and Undo restore a coherent selection and viewport. Touch and keyboard alternatives accompany every new direct manipulation.

0. Stabilize the foundation before adding controls

Outcome: a new gesture cannot break existing shape dragging, endpoint dragging, queueing, or Undo.

Engineering
Reuse the existing app.js revision, render-version, draft, Undo/Redo, and persistence paths. Introduce a small shared edit-session boundary only where needed: begin, preview, validate, commit, cancel. Centralize the displayed document state instead of allowing transient status messages to imply a different revision. Keep documents.js persistence and worker.js native validation; do not build a second history system.
Render safety
Coalesce superseded live previews; discard late results by document identity, source revision, and edit-session token. Logical cancellation must prevent stale results from reaching history or the canvas even when a WASM job cannot be interrupted. Keep the last valid scene and current invalid input recoverable. Retain worker timeouts and input limits.
Gesture ownership
Define explicit select, pan, place, connect, text, and resize modes. Handles own their pointer gesture; empty-canvas actions follow the active mode. A second touch cancels an uncommitted object manipulation before pinch navigation takes over. Pointer cancellation, lost capture, Escape, and document switching cancel safely. Suppress accidental SVG text selection only on the interaction surface, not in editable text fields.
Acceptance
Rapid edits, delayed renderer responses, mode switches, and failed renders cannot commit stale changes. Queue mode displays all queued changes; auto-apply commits only validated results. Existing Undo/Redo and draft batch behavior remain intact. “Saved on this browser” appears only after successful storage. Selection never focuses code automatically.

1. Edit labels directly; make sizing explicit

Outcome: long text no longer unexpectedly overruns a shape, and editing a label does not require scrolling to an inspector.

Interaction
Enter or a selected-object “Edit text” button opens a canvas-anchored editor on desktop and a compact keyboard-safe sheet on phone. Double-click remains optional. Use a multiline input: Enter inserts a line break, Ctrl/Cmd+Enter or a visible Done button commits, Escape or Cancel restores the original. IME composition must not accidentally commit. Keep focus in the editor while preview renders; return to the selected object after completion.
Sizing policy
Grow uses supported native fit behavior. Wrap preserves a chosen width and emits valid multiline Pikchr labels while allowing height to grow. Fixed preserves both dimensions and explicitly warns about overflow. Explain that wrapping is materialized into source lines; imported documents do not magically recover an original paragraph or hidden editor policy.
Engineering
Extend properties.js and property-ui.js; put the new editor in a focused module rather than expanding every selection handler. Reuse fitText, changeText, and source patches. Prototype wrapping against native-rendered bounds with a bounded number of measurements; account for usable interior width on cylinders, circles, and diamonds. Never “fix” overflow with CSS over the SVG. Initial wrapping may be restricted to boxes until other shapes have tested interior-bound rules.
Acceptance
“The Node of the Day,” multiline labels, CJK, emoji, and long unbroken words are handled predictably. Grow and supported Wrap cases fit; Fixed warns. Quotes and backslashes are currently rejected by the text encoder: add encoding only after renderer round-trip tests prove it, otherwise retain a clear restriction without changing source. Cancel writes nothing; Done creates one transaction, not one per keystroke.

2. Place shapes and add connected neighbors

Outcome: creating a small flow starts on the canvas, not in coordinate forms.

Interaction
Choose a shape, then click or tap its position. Show a placement preview and visible Cancel; select the result and offer label editing. Default to one-shot placement. “Keep adding” is an explicit toggle. A selected node offers “Add connected shape” with direction choices usable by touch and keyboard—never a hover-only control.
Engineering
Reuse creation.js, creation-ui.js, naming rules, and shape types. Convert screen coordinates using the current SVG transform, including pan and zoom. Insert a neighbor and its connector as one candidate source change, resolving names and source-order dependencies before validation. Use a deterministic default gap; do not imply this performs whole-diagram layout.
Acceptance
Tool selection plus one canvas tap places a node at every supported zoom. Creating a connected neighbor never needs separate node and edge forms. One Undo removes both. Cancel, a missed tap, or a failed render does not leave half an insertion. Keyboard users can place at viewport center and nudge or specify coordinates.

3. Make connector editing one coherent mode

Outcome: users can create connections, reattach either end, and change arrowheads without hunting among panels.

Interaction
Connect mode supports source-then-target taps and optional handle dragging. Enlarge hit areas without enlarging the visible diagram. Show the target object, anchor name, and attachment cue during targeting. A selected connector exposes From, To, start/end termination, Reverse, label, and route actions nearby. A missed drop restores the original connection.
Engineering
Unify existing arrow-ui.js, route-ui.js, endpointCandidates in edits.js, and changeTermination in properties.js; endpoint editing and termination support already exist. Start with fixed native anchors. Defer automatic-side policy until its source behavior is explicit. Reverse must deliberately exchange endpoints and route order while preserving labels and intended arrowhead semantics.
Acceptance
Both endpoints can be reattached on a phone without precise dragging. None/start/end/both terminations round-trip through native Pikchr. Target validity is conveyed by text or shape cues as well as color. Connector mode, shape dragging, pan, and resize never compete for the same gesture. One finished reattachment is one transaction.

4. Resize with handles, guides, and predictable text

Outcome: changing shape dimensions is visual and does not silently damage labels or connections.

Interaction
Show handles only for safely resizable shapes; retain numeric controls as a precise alternative. Add alignment and equal-spacing guides with a visible snap toggle. Touch targets should be at least 44 CSS pixels where practical. Keep the opposite edge fixed for edge drags; offer explicit aspect-ratio locking. Circle resizing remains uniform.
Engineering
Reuse numeric property patches and overlay transforms from app.js, properties.js, and property-ui.js. Add geometry helpers rather than altering native SVG as the final result. Resolve sizing-policy conflicts visibly: an explicit width drag on a Grow box proposes Wrap; an explicit height constraint proposes Fixed. Supported anchor references are re-evaluated by the renderer. Do not silently rewrite unrelated coordinates to simulate attachments.
Acceptance
At different zoom levels, handles track the pointer, minimum dimensions remain valid, and snap can be disabled on phone. Text follows the chosen policy; connectors attached by anchors stay attached. The validated SVG matches the accepted preview. Unsupported dimension expressions remain read-only with a reason. One drag is one Undo step.

First-release gate: complete slices 0–4, then run the full editing journey below before adding richer routing or grouping.

5. Suggest better routes without taking over the drawing

Outcome: “Tidy route” offers a cleaner, inspectable alternative for a selected orthogonal connector.

Engineering
Add a separate pure routing module called from route-ui.js. Start with finite rectangular obstacle bounds, clearance, fixed endpoints, and deterministic tie-breaking. Generate a small candidate set using a bounded search grid; rank by collisions, endpoint approach, bend count, then length. Treat explicit retained bends as constraints. Present the candidate before accepting it into the shared transaction path.
Acceptance
Golden fixtures cover close shapes, blocked exits, coincident ports, narrow corridors, pinned bends, and no-solution cases. Search has a fixed node/time budget and does not freeze editing. Failure keeps the existing route. Repeated input produces the same source. Do not promise crossing-free graphs or automatic routing for arbitrary imported expressions.

6. Select and reuse a whole section

Outcome: a useful three-node fragment can be copied, moved, or saved for reuse as a unit.

Interaction and engineering
Extend existing multiselect and object-actions.js with explicit marquee mode plus a touch-friendly object-list alternative. Add copy/paste for the supported subgraph subset, fresh identifiers, a source-order dependency check, and a preview of omitted external edges. Begin with an app-local clipboard; expose system clipboard only with graceful permission failure. Build reusable components on the same validated insertion operation, not another serializer.
Acceptance
Internal edges and supported labels survive copying; names never collide. External dependencies are reported before insertion, never silently detached. One paste is one transaction. Unsupported partial groups or ambiguous references fail without mutation. Selection collections are described as editor selections—not native Pikchr groups.

7. Make examples, source learning, and recovery trustworthy

Outcome: users know what they can edit, understand a suggested change, and can recover their work outside this browser.

Examples and teaching
Keep the current example-picker.js native previews and safe opening flow. Add purpose, complexity, and “fully editable / partially editable / source only” labels. Add small learning examples alongside showcases. Build concise explanations from edit metadata and offer an expandable source diff without focusing the code pane. State must already be truthful from slice 0; this adds explanation, not a second preview.
Backup and export
Extend documents.js with a versioned downloadable workspace backup containing documents, draft/history, and explicit editor metadata. Validate restores before creating copies; do not overwrite current documents implicitly. Keep source export distinct from backup. Add selected-region SVG and PNG export using native SVG with bounded raster dimensions; strip editor overlays, preserve padding, and report font or export failures.
Accessibility and acceptance
All new actions are keyboard reachable and have stable accessible names, visible focus, and tap alternatives. Announce committed changes and errors without narrating every pointer movement. Verify object-list navigation and keyboard-only editing. Example previews do not mutate the current document. Storage quota failures remain visible. Backup/restore round-trips drafts and history; exported source re-renders without editor-only geometry.

8. Expand the source model before promising native group editing

Outcome: a separate design decision defines which richer Pikchr constructs can be edited safely.

Investigate stable source-to-object identities, nested scopes, dependency-aware patching, and explicit anchors for triangle/trapezoid composites. Prototype one native group and one composite with source round-trip tests before adding a library. Moving statements to mimic layers can break prior-object references; do not treat source order as an unrestricted z-order list.

Gate: choose a supported syntax boundary and migration strategy based on fixtures. If reliable mappings need renderer metadata changes, make those changes narrowly and test existing source compatibility. Keep unsupported constructs inspect-only. This slice is not a commitment to a general bidirectional Pikchr parser.

Defer collaboration, accounts, AI generation, broad icon catalogs, and general freehand drawing. They do not solve the current editing-loop problems.

Verification and release gates

Verified baseline, 20 September 2026: npm test passes 79 tests, with zero failures. That is the Node/native test baseline, not evidence that browser interaction scripts or physical-phone tests passed. npm run build invokes the existing build script; run it when renderer/build assets change.

  1. Pure source tests: extend existing creation, edits, properties, documents, navigation, worker, and example-picker tests. Add transaction, wrapping, resize, and routing fixtures as their slices land. Assert unchanged source outside intended patches, correct UTF-8 offsets, valid native output, and atomic rejection of unsupported inputs.
  2. Browser regression journeys: reuse the existing drag-interior-browser.py, queue-browser.py, properties-browser.py, fit-browser.py, creation-browser.py, polish-ui-browser.py, and workflow-browser.py where applicable. Inspect each script’s setup before execution; they are not claimed to be one automated test suite. Add interaction assertions for focus, gesture cancellation, and state synchronization.
  3. Adversarial corpus: exercise Unicode, escaped text, unbroken words, duplicate names, relative references, groups/macros, imported source, empty diagrams, source-size limits, renderer timeout, delayed responses, storage failure, and reload with a pending draft. Include simple pipeline, long-label decision flow, and detailed Gitflow.
  4. Real-device acceptance: iOS Safari and Android Chrome, portrait and landscape, with the on-screen keyboard visible. Test drag versus pan, pinch, both endpoints, visible action reachability, focus restoration, and Undo. Desktop viewport emulation supplements but does not replace this gate. Physical-phone acceptance remains unverified; user or device access may be required to close it.

The release journey

Open a blank document → place a box → type a long label → wrap it → create a connected neighbor → change both terminations → reattach each endpoint → resize → pan and zoom → Undo and Redo → repeat in queue mode → apply the batch → reload → export and re-render. Later releases append route cleanup, subgraph paste, and backup restoration.

Pass criteria: no lost source, stale commits, unexpected code focus, accidental text selection, or diagram/source mismatch; one transaction per completed operation; clear cancellation and error recovery. Record task time, panel changes, wrong actions, and accidental pans before and after. These are proposed acceptance criteria, not invented competitor benchmarks.

Next implementation action: start slice 0, then deliver slices 1–4 as the first usable release. The order does not require another approval for every slice once implementation is authorized. Stop for a genuine source-destructive decision, a material scope change, or required device access—not ordinary engineering choices. This turn delivers the plan only; no app behavior changed.
