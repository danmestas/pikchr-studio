Better everyday editing in Pikchr Studio

UX parity research and recommended backlog · 20 September 2026

Recommendation: borrow Excalidraw’s direct manipulation, draw.io’s connection controls, and Mermaid’s immediate code feedback. Keep Pikchr source as the portable, readable document—not a by-product of an unrelated drawing model.

ResearchCurrent gapsPrioritiesDelivery and acceptance

Method: official competitor documentation plus a read-only inspection of Studio’s current implementation. This is not a timed, hands-on competitor benchmark. Phone and assistive-technology behavior still need physical-device acceptance tests. Assumed audience: a solo technical author using desktop and phone. These are recommendations, not implemented changes.

What each tool teaches us

Mermaid: shorten the distance between intent and a valid diagram

The Live Editor offers code with immediate preview, samples, browser-local history, and export. Mermaid’s commercial visual-editor product is separate; its features should not be attributed to the open-source renderer or Live Editor. Official getting-started guide.

Mermaid flowcharts describe nodes and relationships with configurable layout rather than requiring every position to be authored. Official flowchart reference. For Studio, borrow “make a useful first draft quickly”: connected-neighbor creation and optional layout suggestions. Do not automatically rearrange a deliberately composed Pikchr drawing after every edit.

Excalidraw: make the canvas the place where work happens

Its documented editor features include shape libraries, bound arrows, labelled arrows, undo/redo, pan/zoom, and portable scene files. The hosted app additionally provides local-first autosave and collaboration; these are not all interchangeable package features. Official project documentation.

The useful lesson is a coherent loop: create → select → type → connect → adjust, without repeatedly travelling to distant forms. Studio has many individual controls but needs this uninterrupted loop.

draw.io: make connections precise and inspectable

draw.io distinguishes floating perimeter connections from fixed points, permits mixed endpoints, supports segment manipulation and connector labels, and makes connection targets visible during dragging. Connector manual. Its quick drawing workflow also combines duplicating a shape with connecting it. Drawing faster.

Studio should expose attachment intent—“fixed east anchor” versus “choose an appropriate side”—and show what moving a node will do to its connectors. That is more useful than simply adding more route presets.

What Studio already has—and what remains awkward

Do not reopen “add Undo,” “add pinch,” or “add examples” as missing-feature tickets. Their implementations exist. Improve discoverability and verify that they work reliably together.

Recommended backlog, in order

Order reflects everyday frequency, interruption severity, and implementation risk. The first four improvements should form one coherent editing loop.

1. Direct label editing and explicit text sizing · Next

Select a shape and press Enter or choose a nearby “Edit text” action; double-click is a desktop shortcut, not the only entry point. Edit in place on desktop and in a compact keyboard-safe sheet on phone. Offer Grow to fit / Wrap to width / Fixed size, with padding and a live native-rendered preview.

Acceptance: the reported long label stays inside its shape in Grow and Wrap modes. Fixed mode warns about overflow. Enter/Escape have clear commit/cancel behavior; multiline typing remains possible. One completed edit is one undo step. Focus stays with the diagram afterward.

Implementation constraint: wrapping must produce valid Pikchr label lines, not merely CSS around SVG text. Test quotes, backslashes, Unicode, long unbroken words, and text near renderer limits; provide a clear error instead of truncation.

2. Place shapes and create connected neighbors · Next

A compact canvas toolbar selects a shape; click or tap the desired location to place it, then type its label. A selected shape exposes “Add connected shape” with a direction choice. Preserve the current numeric inspector as an advanced option.

Acceptance: placement takes tool selection plus one canvas tap; adding a connected neighbor does not require opening separate shape and connector forms. The new node and edge undo together. Escape cancels; repeated placement is an explicit mode with a visible exit.

3. A complete connector editing mode · Next

Choose “Connect,” then source and destination; also allow dragging from visible handles on desktop. Show an enlarged endpoint target, the intended attachment, and a live route. Put start/end decorations, reverse, label, and route controls next to the selected connector.

Acceptance: both endpoints can be reattached without scrolling. Mobile has a two-tap alternative to precise dragging. A missed drop preserves the old connection. Attached versus unattached endpoints are distinguishable without color alone. Do not steal focus into source code.

Keep fixed native anchors first. “Automatic side” needs a documented editor policy that resolves to valid source after each edit—not a promise that arbitrary imported Pikchr gains persistent routing semantics.

4. Resize handles, alignment guides, and predictable snapping · Next

Add visible selection handles with larger touch hit areas. Resize the object while previewing text and connected edges. Show alignment and equal-spacing guides; provide a visible snap toggle as well as a desktop modifier.

Acceptance: resizing a rotated or unsupported construct is disabled with an explanation, not silently approximated. Supported shapes preserve attachment relationships. One drag is one undo step, and the freshly re-rendered SVG matches the preview.

5. Suggest cleaner orthogonal routes · Following

Offer “Tidy this route,” with a preview, for avoidable crossings through shapes and awkward detours. Preserve user-pinned bends; reroute only affected connectors. Begin with rectangular obstacles and explicit supported cases.

Excalidraw’s engineering account shows why this is a distinct project: pleasing elbow routes require constraints beyond a shortest line, and its later implementation uses a reduced search grid and A*. Part one · Part two.

Acceptance: deterministic output, no traversal through supported obstacles, correct endpoint approach, and a bounded computation budget. If no acceptable route exists, retain the old route and explain why. Do not claim crossing-free routing in arbitrary graphs.

6. Select, duplicate, and reuse a whole section · Following

Add marquee selection, a touch-friendly selection mode, common-property editing, and copy/paste of supported subgraphs. Copy included edges, generate fresh identifiers, and clearly handle edges leaving the selection. Then add “Save selection as reusable component.”

Acceptance: a copied three-node flow remains internally connected, never collides with existing names, and undoes once. Unsupported dependencies are reported before insertion. A selection set is not falsely presented as a native Pikchr group.

7. Make source feedback teach without interrupting · Following

Use one authoritative diagram preview. Show “Applied,” “Draft: 3 changes,” or “Invalid—showing last valid diagram” with Undo nearby. Let users expand a compact source difference and a plain explanation such as “Moved B using A.e as its reference.” Never focus the code pane merely because selection changed.

Acceptance: the displayed diagram’s status cannot be confused with pending source. Failed validation preserves both recoverable input and the last valid result. Unsupported edits explain the specific restriction and offer source editing without modifying anything automatically.

8. Improve examples and reusable starts · Following

Keep the new previews. Add purpose, complexity, and capability labels: “fully editable,” “partially editable,” or “source only.” Include small task-oriented starts—decision flow, grammar fragment, architecture, branching—not only finished showcase diagrams. Separate browsing from opening a copy.

Acceptance: opening and closing previews never changes the document. Selecting a nested-group example warns about editing limitations before opening. “Start blank” and “Open as new document” remain obvious on a phone.

9. Recovery, export, and accessibility polish · Continuous

Make local storage status explicit, add named checkpoints and a downloadable workspace backup, and distinguish source export from a backup that preserves history and editor settings. Add selected-region SVG and PNG export with predictable bounds. Provide keyboard-reachable canvas actions, labelled controls, visible focus, and a screen-reader object list.

Acceptance: restoring a backup is tested; storage failure is not reported as “saved.” Every core gesture has a keyboard or tap alternative. Export excludes selection handles and includes the expected labels and padding.

10. Groups, layers, and custom shapes · Later, after a source-model design

These are valuable, but are not simple toolbar additions. Native groups, arbitrary source expressions, and shape composites need reliable source-to-object mapping. Reordering statements to simulate layers can break references. Begin with editor-only locks and selection collections; separately design native group editing and triangle/trapezoid composites with stable anchors.

Acceptance: exported Pikchr reproduces the drawing in a clean renderer. No hidden SVG-only geometry and no silent flattening of the author’s source.

How I would deliver it

  1. First, close the regression gate. Test current endpoint dragging, shape dragging, undo/redo, source focus, example switching, pan and pinch on physical iOS Safari and Android Chrome. Browser viewport emulation alone does not close this gate.
  2. Then ship the core loop: label editing and sizing → canvas placement and connected neighbors → connector mode → resize and guides. Keep tests for earlier interactions running during each slice.
  3. Then tackle richer diagrams: route suggestions, subgraph copy/paste, reusable components, source explanations, and recovery/export improvements.
  4. Finally extend the language-aware editor: editable native groups and custom composites. Defer collaboration, accounts, AI generation, and huge icon catalogs until everyday editing is trustworthy.

A repeatable acceptance session

Use the simple pipeline, a long-label decision flow, and the detailed Gitflow example. Create a node; type a long label; change its shape; connect it; reattach both ends; move a bend; resize; select and duplicate a section; undo/redo; switch examples; export and re-render.

Record completion, wrong actions, panel changes, accidental pans, lost focus, and source/preview mismatches. Proposed targets: no forced code focus, no unintended text selection, no silent lost edits, one undo per semantic operation, and no diagram/source mismatch after validation. Measure task times before and after rather than inventing competitor timing targets.

Bottom line: the next release should make “put a shape here, type in it, connect it there” feel natural. That would improve practical parity more than another dozen features hidden in panels.
