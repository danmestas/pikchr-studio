  • Created a card-stack diagram through visible controls: 15 boxes and 3 arrows, 18 objects. UI-built source.
  • Pasted the actual Figure 12 source into the visible Source field and rendered its 18 objects, then attempted visual editing.
  • The UI-built examples reproduce comparable topology and object counts, not exact visual replicas. Their formatting gaps are part of the evidence.

All interaction evidence came from computer use in isolated browser tabs. No programmatic DOM changes or direct rendering-engine calls were used to create the examples. Original issue details and acceptance criteria

Historical observations are intentionally unchanged below. Consult Current implementation status before interpreting an issue as still open.

P1 = address before expanding authoring features; P2 = important capability or workflow improvement. Order combines severity, likely frequency, and implementation leverage; effort estimates require engineering investigation. These are local backlog entries, not externally filed issues.

PKUX-001 · P1 · Recover work after reload

Evidence / reproduce
Reproduced: build the 18-object stack, Apply all, reload. The app returns to the five-object Pipeline example with no restoration. The audit recovered using previously captured source.
Impact
A normal browser action discards work; “Applied” can be mistaken for saved.
Recommended change
Persist the working document locally, including pending draft state; distinguish Applied, Saved locally, and Downloaded. Explain storage limits.
Acceptance
Reload restores both applied and pending work without silently applying or discarding it. Recovery is offered after an interrupted session. Persistence failure is visible. New document cannot silently overwrite recoverable work.

PKUX-002 · P1 · Make selection safe while connector endpoints are active

Evidence / reproduce
Reproduced: select Link6, from Shape7.se to Shape9.n, in endpoint mode. Click the center of Shape1 intending to select it. Link6 reconnects to Shape1.c under auto-apply, without an endpoint drag. Undo recovers.
Impact
A navigation action silently changes diagram meaning.
Recommended change
Require an explicit endpoint drag or clearly entered Reconnect action. An ordinary object click should select that object; Escape should exit reconnection.
Acceptance
Clicking any unrelated shape after selecting a connector changes selection only. Endpoint drag still reconnects. Cancellation leaves source unchanged. Cover auto-apply and queue modes.

PKUX-003 · P1 · Keep focus in the diagram during selection

Evidence / reproduce
Reproduced: click Shape1 in the Objects list. The Pikchr source textarea gains focus and selects the statement; the focused source has a blue outline.
Impact
Selection pulls attention away from the manipulation workflow and makes repeated editing feel like navigation between tools.
Recommended change
Separate selection from source navigation. Highlight matching source without moving focus; provide explicit Show source.
Acceptance
Mouse selection keeps focus on the activating control or canvas, and does not scroll to source. Keyboard selection retains usable keyboard focus. Show source deliberately focuses the matching statement.

PKUX-004 · P1 · Keep larger diagrams readable

Evidence / reproduce
Reproduced: the nine-node tree displays tiny labels, with anchor circles covering text. Select Link6 → Endpoints → uncheck Anchors: target anchor circles remain visible on all nine shapes. No exposed zoom, pan, fit-view, fullscreen, or source-collapse controls were found.
Impact
Users lose readable labels and reliable hit targets precisely when diagrams become useful.
Recommended change
Add zoom, pan, Fit view, and a diagram-focused layout. Reveal anchors only when relevant; avoid label overlap.
Acceptance
The gate and stack fixtures can be read and edited at a useful scale without browser zoom. Zoom preserves the point of interest; Fit view restores the entire diagram. Anchors do not obstruct ordinary text selection targets. The Anchors toggle hides target anchors, except during a deliberately initiated reconnect gesture.

PKUX-005 · P1 · Put selection actions beside the canvas

Evidence / reproduce
Observed: connector routing and property controls sit in the separate Inspector. Authoring repeatedly requires selecting the diagram, finding controls, then returning to the diagram. Route guidance refers to preview/review even when auto-apply is active. Reproduced: toggling Anchors moves the Connector section above Text/Arrowheads, pushing those properties below the fold; reselecting Link6 restores their previous order. The controls move; they are not deleted.
Impact
The core edit loop involves unnecessary attention and navigation changes; instructions do not consistently explain what committing an edit will do.
Recommended change
Add a stable preview toolbar with contextual Text, Fit, Shape, Route, Arrowheads, and Reconnect actions, plus visible status and Undo. Show Apply/Discard only in queue mode.
Acceptance
Common text and connector operations start from the preview without searching a distant panel. Controls remain discoverable without covering diagram content and retain consistent order after toggles and reselection. Every commit hint accurately describes the active apply mode.

PKUX-006 · P1 · Support multiline labels and standalone text

Evidence / reproduce
Reproduced: Shift+Enter in Object text does not insert a newline; the field is single-line. Figure 3 needs five-line leaf labels and an independent title. No Text option was found among box, circle, ellipse, oval, cylinder, and diamond.
Impact
Reference-like labels and titles require source editing, not direct authoring.
Recommended change
Provide multiline label editing with explicit line-break behavior, and an independent text object.
Acceptance
Create and edit a five-line label and an independent title without source edits. The generated Pikchr rerenders with the same breaks, labels remain editable, and Fit accounts for every line.

PKUX-007 · P1 · Add predictable sizing and alignment

Evidence / reproduce
Observed: fitted card rows range from roughly 0.456 to 1.0 wide at 0.210 high. No width/height, resize handles, equal-width, align, distribute, or multiselect controls were found.
Impact
A stacked-card visual cannot be made into clean, equal-width rows through exposed controls.
Recommended change
Add explicit dimensions and resize handles, then multi-selection with equal width, edge alignment, and spacing distribution. Make fit-vs-fixed-size behavior explicit.
Acceptance
Build a five-row stack with common width, aligned edges, and consistent spacing without manual source edits. Moving or resizing it keeps anchored connectors attached. Undo restores the whole layout action.

PKUX-008 · P1 · Explain and expand visual-edit compatibility

Evidence / reproduce
Reproduced: import actual Figure 12 and Render. Dragging Y1 is a no-op with “Placement or attributes outside supported literal subset”; Fit is disabled and type controls are absent. Selecting arrow o5 reports inspect-only connector editing despite explicit G1.sw to Y1.n references. The source includes dimensions, hex colors, and relative expressions; the exact rejecting construct was not isolated.
Impact
Valid, rendered Pikchr unexpectedly becomes visually uneditable. Generic explanations do not tell the user what to change.
Recommended change
Identify the exact unsupported construct and offer safe targeted edits or an explicit, previewed conversion. Expand supported syntax based on these real fixtures, without silently flattening relationships.
Acceptance
Each disabled operation identifies its precise reason and workaround. Regression tests cover the original Figure 12. Supported changes preserve unrelated styling and relative relationships; unsupported cases never imply a successful edit.

PKUX-009 · P2 · Start and open documents explicitly

Evidence / reproduce
Observed: no New, Blank, or Open control was found. Starting from blank required clearing Source and clicking Render.
Impact
Basic document work begins with a source-code workaround and risks overwriting existing work.
Recommended change
Add New diagram, Open source, and an obvious example picker with unsaved-work protection.
Acceptance
Start blank or open a downloaded Pikchr file without editing the source field. Existing work is recoverable or explicitly discarded.

PKUX-010 · P2 · Duplicate and repeat objects efficiently

Evidence / reproduce
Reproduced: every new shape requires Label, X, Y, and submit. After creation the label resets to “New shape”, X moves rightward, and Y resets to zero. No duplicate control was found.
Impact
Repeated leaf nodes and stack rows require many repetitive entries and coordinates.
Recommended change
Add Duplicate with predictable placement and unique names; preserve useful creation settings and offer click-to-place.
Acceptance
Duplicate a styled row four times, edit its labels, and arrange it without re-entering dimensions or type. Names remain unique, existing connections stay unambiguous, and each action is undoable.

PKUX-011 · P2 · Use human-readable object identities

Evidence / reproduce
Observed: Objects and connector selectors expose Shape1…Shape9 and Link1…Link6 rather than the displayed labels; no rename control was found.
Impact
Connecting or selecting nodes requires memorizing an ID-to-label mapping.
Recommended change
Display label plus stable ID, highlight candidate objects on selection, and provide safe renaming where supported.
Acceptance
Connector selection distinguishes similarly named nodes and identifies the intended visible node without counting shapes. Renaming updates references safely or clearly explains why it cannot.

PKUX-012 · P2 · Accept reasonable decimal coordinates

Evidence / reproduce
Reproduced: Add shape X/Y step validation rejects −0.25, −0.75, and −2.55. The native message says the nearest valid values to −0.25 are −0.3 and −0.2. Values −0.2, −0.7, −1.3, and −2.6 were used as workarounds.
Impact
Valid intended placements cannot be submitted; the form can appear not to create the object. This was native step validation, not an observed asynchronous lost-edit bug.
Recommended change
Accept finite decimal coordinates at useful precision; make grid snapping an explicit, optional manipulation behavior.
Acceptance
All three rejected sample values submit and render at their intended positions. Invalid/nonfinite input has an inline explanation; snapping never silently changes entered coordinates.

PKUX-013 · P2 · Position connector labels deliberately

Evidence / reproduce
Reproduced: a “yes” label renders on a horizontal-first route. No label-position control was found.
Impact
Branch meaning is harder to read, and authors cannot move a label away from geometry through the inspector.
Recommended change
Offer label placement along the route and an offset from it, with sensible default clearance.
Acceptance
Move “yes” to an unambiguous branch segment with clear separation from its line. Rerouting preserves an understandable label position and does not overlap an endpoint.

PKUX-014 · P2 · Add and remove route bends

Evidence / reproduce
Observed: three route presets are exposed and an existing square route handle can be dragged. No arbitrary bend insertion/removal control was found.
Impact
Routing around multiple intervening cards cannot be authored as freely as the underlying diagram language allows.
Recommended change
Add explicit bend insertion/removal and constrain segments predictably, retaining presets for simple cases.
Acceptance
Create a multi-bend path around an obstacle, remove a bend, and preserve both endpoint attachments. Show the resulting valid source; invalid geometry can be cancelled without changing the document.

PKUX-015 · P2 · Expose semantic styling

Evidence / reproduce
No exposed fill, stroke, font, or style controls were found. The reference uses a rust-colored changed branch and contrasting card-header backgrounds.
Impact
Meaning encoded by color or emphasis requires source edits.
Recommended change
Add basic fill, line color, line weight, and text styling, with clear defaults and a reset action.
Acceptance
Style the changed branch and header rows through controls. Existing imported colors survive unrelated edits. The same distinction can also be represented without relying on color alone.

PKUX-016 · P2 · Treat repeated panels as movable units

Evidence / reproduce
No grouping or duplicate-panel control was found while building the 15-row stack diagram. Reproduced in the 18-object stack: Shift-click Shape1 then Shape10 in Objects leaves only Shape10 pressed, not a multi-selection.
Impact
Moving or reusing a five-row panel requires treating each row separately, risking broken alignment.
Recommended change
Support multi-object movement and reusable grouped panels, explicitly distinguishing visual selection groups from native Pikchr grouping semantics.
Acceptance
Move or duplicate a complete five-row panel in one operation. Internal layout remains intact, names are unique, and connector treatment is explicit and undoable.

PKUX-017 · P2 · Delete selected objects safely

Evidence / reproduce
No delete-selection control was found in the inspected toolbar or inspector. Reproduced: focus Rendered diagram and press Delete in the stack specimen; all 18 objects remain. Manual source editing remains a fallback.
Impact
Removing a mistaken object requires source knowledge and consideration of references.
Recommended change
Add Delete with a preview of dependent connectors and a clear policy for dangling references.
Acceptance
Delete a leaf or connected node through the UI without producing invalid Pikchr. The user can see which connectors will also change; Undo restores the complete prior state.

PKUX-018 · P2 · Review and amend an entire queued batch

Evidence / reproduce
Reproduced: 18 queued changes update source and diagram and Apply all succeeds. While pending, source is readonly and auto-apply is disabled. Review exposes the latest diff and Undo last change, not a full batch comparison or arbitrary amendment.
Impact
The longer the successful queue becomes, the harder it is to understand or correct an early mistake.
Recommended change
Show a base-to-current diff and meaningful history labels; support stepping back or amending safely. Explain the source lock and mode-switch constraints.
Acceptance
Review all 18 changes against the initial document, identify an earlier edit, and recover without unexpectedly discarding unrelated work. Any dependency restriction is explained before the operation.

PKUX-019 · P2 · Export the rendered artifact

Evidence / reproduce
Observed: Download source is exposed; no SVG export control was found.
Impact
Authors can preserve code but cannot finish the documentation handoff from the same workflow.
Recommended change
Add Download SVG and Copy SVG for the displayed valid diagram, clearly identifying whether it represents pending or applied state.
Acceptance
Export both fixtures as standalone SVGs matching the visible diagram, without editing handles or selection overlays. Source download remains available and its state is explicit.
